# i18n (roadmap Phase P)

> Multilingual forms: render one schema in many languages. Decided after the V2→R2→R7
> direction completed. Slice it like V2 — ship the renderer-facing API first, builder UI
> later. Tick the boxes as each sub-phase lands.

Status legend: ⬜ todo · 🟡 in progress · ✅ done.

## Locked decisions (2026-06-20)
1. **Strategy = per-node inline `i18n` override maps** (NOT a central catalog). Each node keeps
   its authored default string and gains an optional `i18n` map `attribute → locale → string`.
   Translations travel with the node (robust to reordering), internal types stay `string`
   (no type ripple), and it mirrors the W4 "snapshot + overrides" pattern. A form-core resolver
   collapses it to a plain `FormSchema` at render time. Additive ⇒ **no `formVersion` bump**.
2. **First slice = contract + renderer only** (no builder UI). Builder translations UI (P2) and
   localized default validation messages (P3) follow as separate slices.

## Contract shape
```jsonc
// field / container node:
{ "name": "email", "label": "Email", "placeholder": "you@example.com",
  "i18n": { "label": { "vi": "Thư điện tử" }, "placeholder": { "vi": "ban@vidu.com" } } }
// static option (flatter — one string): { "label": "Male", "value": "m", "i18n": { "vi": "Nam" } }
// form level (for `title`): "i18n": { "title": { "vi": "Khảo sát" } }
```
Translatable surfaces: form `title`; leaf `label`/`placeholder`/`helpText`/`tooltip`/`extra`;
container `label`/`title`/`description`; `display-text` `content`; static option `label`.
**Deferred to P2:** hierarchical option labels (`cascader`/`tree-select` `treeOptionSchema`,
including nested `children`) and validation/async `message` strings — see P3.

## Phase P1 — contract + renderer  ✅
**Branch:** `feat/i18n-p1` (off `feat/r7-form-layout`) · **Packages:** form-schema + form-core +
form-renderer-web (all changeset minor).

- `form-schema`: `i18nMapSchema`/`I18nMap`; optional `i18n` on `commonFields` (all leaves),
  every container, `display-text`, `optionSchema` (locale→string), and `formSchema` (title).
  Additive, no `formVersion` bump (parse-compat test, not a migration).
- `form-core`: new `localizeForm(form, locale, fallbackLocale?)` (`src/localize.ts`) — deep-clones,
  overrides each node's text attrs + option labels + form title for the locale (fallback chain),
  strips the `i18n` maps; descends via the shared `childrenOf`. Exported from the barrel.
- `form-renderer-web`: `FormRenderer.locale?`/`fallbackLocale?`, resolved as the last step of the
  `migrate → resolveLinkedFields → localizeForm` pipeline; `imperative.tsx` forwards them. Absent
  `locale` ⇒ runtime unchanged.
- Tests: schema parse/compat/reject; `localize.test.ts` (override/fallback/options/nested/title/
  no-op); `FormRenderer.i18n.test.tsx` (vi labels + option text; default with no locale).

**DoD:** typecheck green, schema/core/renderer tests green, biome clean, 3 changesets, no
`formVersion` bump, reviewer PASS.

## Roadmap after P1 (separate slices)
- **P2 — builder translations UI:** form-level locale config (`defaultLocale`/`locales`) + a
  per-field "Translations" editor writing `node.i18n` + a locale switcher in canvas/preview.
  Also extend the contract + `localizeForm` to **hierarchical option labels** (cascader/tree-select
  `treeOptionSchema`, recursing into `children`), deferred from P1.
- **P3 — validation messages:** localize form-core's *default* generated messages via locale
  message packs, plus optional `i18n` on `validationRule.message` / `asyncValidator.message`.
- **P4 (later) — native renderer** locale parity (the resolver is already shared via form-core).
