# Framework Constitution

> **Artifact nature:** Normative (L1 — Governance Core)
> **Status:** Active · **Version:** 1.0 (semver-lite) · **FRAMEWORK_VERSION:** 1
> **Authority:** Owner (ratified 2026-07-03) · **Amendment:** owner-only, see §15
> **Supersedes:** `decision-records/README.md` → "Architecture freeze" interim record
> (that section becomes a pointer; the binding text now lives here, §11).
> **Verified-on:** 2026-07-03 · **Cadence:** review on every framework-version bump.

This is the top of the framework's normative stack. It is **tool-agnostic**: it must
survive the replacement of Claude Code with any other execution tool (see §2, the
replacement test). Nothing Claude-specific belongs here — those are L3 bindings.

The framework governs how AI agents (and humans) do engineering work in **this**
repository. It is generated by extracting the repository's real practice, not from
generic templates. Its prime directive: keep AI context grounded in verified reality and
prevent stale knowledge from poisoning decisions.

---

## 1. Self-similarity principle

The framework mirrors the architecture of the product it governs. This is deliberate: the
team already trusts these shapes, so the framework inherits their guarantees.

| Product concept | Framework counterpart |
|---|---|
| `form-schema` — the one versioned contract | Governance Core (L1) — the one normative contract |
| `form-core` — shared platform-free runtime | Knowledge (L2) — shared, provenance-stamped facts |
| Renderers — platform-specific adapters | Execution Adapters (L3) — tool-specific bindings |
| `formVersion` + migrations (never break old JSON) | `FRAMEWORK_VERSION` + additive standards (§12) |
| Zod validation at the boundary | Evidence gates + impact manifests (§7, §9) |

Consequence: reasoning about the framework reuses reasoning about the product. A change
that would be illegal in the product (breaking the contract, eval-ing untrusted input,
duplicating validation in an adapter) is illegal in the framework by analogy.

## 2. The four layers

Dependencies point **downward only**. A higher layer may cite a lower one; a lower layer
never depends on a higher one.

- **L0 — Reality.** The repository itself: code, config, git history, tests. The ground
  truth. Every claim ultimately traces here.
- **L1 — Governance Core.** This constitution + policies + charters + procedures + decision
  records. Tool-agnostic, owner-authority. Rules originate here and nowhere else.
- **L2 — Knowledge.** Extracted, provenance-stamped facts about L0 (architecture docs,
  standards, registries, runbooks). Every entry carries a freshness contract (§10).
- **L3 — Execution Adapters.** The bindings that make a specific tool obey L1/L2 (for now:
  Claude Code skills, agents, `CLAUDE.md`, `.cursor/rules`). **Regenerable** — never the
  sole home of any rule or fact.

**Replacement test (invariant):** if the execution tool is swapped, only L3 is rewritten.
If a fact or rule would be lost by deleting all of L3, it was in the wrong layer — promote
it to L1/L2 before it can be lost.

**Prompts never originate rules.** A rule stated only in a prompt/binding and not traceable
to L1 is not a rule; it is a bug in L3.

## 3. Authority model

Who may decide what. Authority does not follow whoever is typing; it follows the layer.

| Scope | Decider | AI agent role |
|---|---|---|
| L1 normative (constitution, policies, charters, ADR acceptance) | **Owner only** | Draft, recommend, never self-ratify |
| L2 descriptive (architecture facts, registries, extracted standards) | Agent + reviewer, owner spot-checks | Author against L0 evidence |
| L3 bindings (skills/agents/rules) | Agent, reviewer, from an Active L1 source | Regenerate; must cite source |
| Reports (audits, drift, reviews, calibration) | No ratification — append-only evidence | Produce honestly, never edit past reports |

The AI **recommends**; the owner **decides** every L1 change. An ADR recommendation is
advisory. This is the same split the decision records already use.

## 4. Precedence stack

When two artifacts conflict, the higher wins. Resolve upward; never let a lower artifact
silently override a higher one.

1. **This constitution**
2. **Accepted decision records (ADRs)**
3. **Policies** (change-approval, DoR/DoD, review-workflow, verification)
4. **Standards** (coding, verification, documentation, design/a11y, release)
5. **Charters & procedures**
6. **L3 bindings** (skills, agents, `CLAUDE.md`, `.cursor/rules`)
7. **A prompt / ad-hoc instruction in a single session**

A conflict discovered at a lower level is a **defect in the lower artifact**, to be fixed
there — not a license to ignore the higher one. If the higher artifact is genuinely wrong,
that is an amendment request (§15 / freeze rule §11), not a silent local override.

## 5. Artifact natures

Every governed file has exactly **one** of four natures. Natures are **never mixed in one
file** — mixing them defeats the review routing that each nature demands.

| Nature | Contains | Review route | Header carries |
|---|---|---|---|
| **Normative** | Rules, constraints, decisions ("MUST/MUST NOT") | Owner always | status + version |
| **Descriptive** | Facts about L0 ("the API has 14 modules") | Agent + reviewer | freshness contract (§10) |
| **Executable** | Runnable checks/methods (scripts, commands) | Pass/fail = the review | the command + expected result |
| **Evidence** | Reports of what happened (audits, smokes, drift) | None — append-only | date + method + result |

A document that states a rule *and* asserts a fact *and* embeds a check must be split into
three registered artifacts.

## 6. Artifact lifecycle

`Draft → Proposed → Accepted → Active → Deprecated → Superseded`

- **Draft** — being written; not authoritative.
- **Proposed** — complete, awaiting the decider named in §3.
- **Accepted** — decided, but not yet in force (e.g., an effective date).
- **Active** — in force; agents must obey it.
- **Deprecated** — kept for reference, superseded by something newer, still readable.
- **Superseded** — replaced; retained only for history and traceability.

A **binding (L3) may only derive from an Active source.** Regenerating a binding from a
Draft/Proposed source violates the freeze and the downward-dependency rule.

## 7. Evidence classes

Every claim carries an evidence class. Higher is stronger. Each work-class sets a **floor**
(the weakest class it will accept) in the DoR/DoD and verification policies.

| Class | Meaning | Example |
|---|---|---|
| **E1 — Executed** | Observed by running it now | test output, live smoke, `ls`/`grep` result |
| **E2 — Source-read** | Read directly from L0 this session | the actual line in `schema.prisma` |
| **E3 — Derived** | Inferred from E1/E2 by reasoning | "therefore 17 repos across 14 modules" |
| **E4 — External** | From an outside source | a library's docs, an upstream changelog |
| **E5 — Recall** | Memory / prior belief, unverified | "I think the port is 3001" |

- Any **behavior** claim needs **E1**. Any **structure** claim needs **E1 or E2**. E5 alone
  never satisfies a governed claim — it must be upgraded before use.
- **Confidence = f(evidence class, age).** A fact is only as strong as its class *and* as
  fresh as its freshness contract allows; an E1 fact past its verify-by date decays toward
  "unverified" and must be re-checked (§10).

## 8. Enforcement ladder

A constraint is enforced at one of four rungs. Constraints **climb** rungs as evidence of
violation accumulates; they start at the lowest rung that works (§14, minimum-viable-rung).

1. **Prose** — written in a governed doc; obeyed by reading.
2. **Structural** — the repo shape makes violation awkward (folder layout, barrels).
3. **Machine gate** — an automated check fails the violation (test, lint, CI, git hook).
4. **Isolated review** — a separate reviewer pass with no stake in the change.

- **Climb-on-evidence:** a rule violated in practice is promoted one rung, with the
  violation as the justification (recorded, not asserted). Governance may always override
  downward pressure to raise a rung.
- **Rung-3 CI-preference:** when a machine gate can live in either CI or a local hook,
  **prefer CI.** CI survives a tool swap and a fresh clone; local hooks do not. A hook is a
  convenience mirror of a CI gate, never the only copy.
- **Advisory-first (mandatory):** a new machine gate runs advisory (non-blocking) for at
  least one phase before it may block. Disabling a *blocking* gate requires a decision record.

## 9. Impact manifest & conformance

Mirrors the product's `formVersion` bump rule (a shape change requires a migration + a test).

- A normative change is **Accepted only when its impact manifest is discharged**: the set of
  every artifact the change affects, each updated or explicitly waived. An undischarged
  manifest blocks acceptance — the same way an un-migrated `formVersion` bump blocks a merge.
- After acceptance, a **conformance sweep** propagates the change to all dependents and
  records residue. The oldest undischarged manifest is a tracked health signal (§13).

## 10. Freshness contract

Every **descriptive** (L2) artifact carries a freshness contract so stale knowledge cannot
silently poison AI context (the framework's founding concern).

- Fields: **scope** (which L0 paths it describes) · **verified-on** (date last checked
  against L0) · **method** (the executable check that re-verifies it) · **cadence** (how
  often) · **class** (§7).
- **Three re-verify triggers:** (a) **per-change** — when the scoped L0 changes; (b)
  **periodic** — when cadence elapses; (c) **at-read** — when an agent relies on it for a
  decision and the date looks stale.
- **Drift = defect, never a silent fix.** Detected drift is filed as a finding and (where
  applicable) a report; it is remediated as its own task, not patched invisibly mid-work.
  Extraction that notices adjacent drift **files** it — it does not refactor inline.

## 11. Architecture-freeze amendment rule (binding)

The blueprint is approved and the architecture is **frozen** (owner ruling, 2026-07-03). No
new architectural idea is adopted post-freeze without passing this gate. Any architectural
proposal MUST, **before any implementation:**

1. Identify the affected ADR(s) it would supersede or amend.
2. Prove the existing architecture insufficient — with **evidence, not preference**.
3. Estimate migration cost.
4. Estimate maintenance cost.
5. Obtain explicit **owner approval**.

A proposal missing any of the five is **not reviewable and is rejected at intake.** This
applies to AI agents and humans alike, **including improvement ideas that arise
mid-implementation** — they are filed as proposals, never acted on inline. The operational
intake form of this gate lives in the change-approval policy (T1.2.1); this section is its
constitutional home and supersedes the interim record in `decision-records/README.md`.

## 12. Backward compatibility & `FRAMEWORK_VERSION`

`FRAMEWORK_VERSION` is a single integer, **decoupled** from any package or doc version, à la
`formVersion`. It is currently **1**.

Four guarantees, mirroring the product's "never break older saved JSON":

1. **Additive standards.** A new standard adds rules with an effective date; it does not
   retroactively invalidate past compliant work.
2. **Supersession over deletion.** A replaced artifact is marked Superseded and kept for
   traceability, not erased (see also the 6-step disposal door, T1.2.3).
3. **Traceability preserved.** Every L3 binding names its L1/L2 source; regeneration keeps
   the trace.
4. **Version bump on shape change.** Changing the *shape* of governance (a new layer, a new
   nature, a new evidence class) bumps `FRAMEWORK_VERSION` with a migration note — the same
   discipline as a `formVersion` bump. Content edits within the shape do not bump it.

## 13. Operating loop & health

The framework runs a continuous loop: **Operate → Observe → Amend → Audit.** Work is done
under the rules (Operate); reports capture what actually happened (Observe); evidence drives
constitutional/policy amendment (Amend); periodic audits check the framework against itself
(Audit, E8).

Health is measured only by signals **computable from existing artifacts** (no new
bookkeeping): share of constraints on ladder rungs ≥2; oldest undischarged impact manifest
(§9); oldest past-due freshness contract (§10); traceability coverage of L3 bindings;
escaped defects found by audit vs. by accident. Baselined in E8.

## 14. Anti-bureaucracy

Process exists to protect correctness, not to accumulate. Three brakes:

- **Minimum-viable-rung.** Start every constraint at the lowest enforcement rung that works;
  climb only on evidence (§8). No speculative ceremony — the no-speculation rule applies to
  the framework itself.
- **Process cost is admissible evidence.** If a rule costs more than the defects it prevents,
  that cost is grounds to demote or remove it — argued with evidence, decided by the owner.
- **Ceremony is removable.** Any step that is not protecting a real, demonstrated failure
  mode may be proposed for removal like any other amendment.

## 15. Amending this constitution

This document is **normative-L1**: only the owner ratifies a change. An amendment follows the
same lifecycle (§6) and, if it touches the frozen architecture, the freeze gate (§11). A
shape change bumps `FRAMEWORK_VERSION` (§12). Every amendment records what changed and why,
so the constitution's own history is auditable — the framework holds itself to the standard
it imposes.
